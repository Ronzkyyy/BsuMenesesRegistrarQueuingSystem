# Per-Service Queues Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each of the 8 student-facing services its own independent queue, instead of 3 services sharing the "Enrollment" queue and 2 sharing the "others"-typed "General Inquiry" queue.

**Architecture:** Add 3 new `QueueDBType`/`QueueType` enum members (`ADDING_DROPPING`, `PETITION_CLASS`, `OTHER_CONCERNS`), migrate the Postgres enum type via the existing rename-swap-drop pattern already used in this repo (`8de3c8b4f094`), insert 3 new `queues` rows for the new types, then repoint the 3 previously-shared services in the frontend's `studentServices.js` to their own new `queueType`. Existing historical tickets stay on their original queue - no retroactive reassignment.

**Tech Stack:** Python FastAPI + SQLAlchemy + Alembic (backend), Vue 3 (frontend). No test framework is configured (per `CLAUDE.md`) - verification is manual against the real running stack.

## Global Constraints

- Do NOT truncate or reassign any existing ticket/queue rows - only add new queue types and 3 new queue rows. The rename-swap-drop enum migration pattern must preserve all existing data (unlike `8de3c8b4f094`, which truncated because old values had no valid mapping - that does not apply here).
- New queue defaults (from the design spec, verbatim):
  - Adding & Dropping: ticket letter `A`, capacity 50, slot duration 15 min, `allow_priority` true.
  - Petition Class: ticket letter `P`, capacity 30, slot duration 20 min, `allow_priority` true.
  - Others: ticket letter `X`, capacity 30, slot duration 15 min, `allow_priority` false.
- The Postgres enum type is named `queuedbtype`, and its stored values are the **uppercase Python enum member names** (e.g. `'ENROLLMENT'`), not the lowercase `.value` strings (e.g. `'enrollment'`) - confirmed by querying the live dev database directly, and already documented in `migrations/versions/0da73afb08b4_add_ticket_letter_to_queues.py`'s comment.
- `general_inquiry` keeps its current `queueType: 'others'` (its queue is already named "General Inquiry" - no change). Only `adding_dropping`, `petition_class`, and `others` (the catch-all service) get repointed to new queue types.
- No "edit queue" endpoint exists (only Pause/Resume/Close/Delete) - the new queues' defaults above are effectively fixed once created.

- [ ] **Step 4: Write the `upgrade()` function**

```python
def upgrade() -> None:
    # Postgres can't safely add enum values and use them in the same
    # transaction, so follow the same rename-swap-drop pattern already used
    # in 8de3c8b4f094 (course/major migration) - but without truncating any
    # data, since real ticket/queue history now exists and must be kept.
    op.execute("ALTER TYPE queuedbtype RENAME TO queuedbtype_old")
    op.execute(
        "CREATE TYPE queuedbtype AS ENUM ("
        "'ENROLLMENT', 'DOCUMENT_REQUEST', 'CLEARANCE', 'SCHOLARSHIP', 'OTHERS', "
        "'ADDING_DROPPING', 'PETITION_CLASS', 'OTHER_CONCERNS'"
        ")"
    )
    op.execute(
        "ALTER TABLE queues ALTER COLUMN queue_type TYPE queuedbtype "
        "USING queue_type::text::queuedbtype"
    )
    op.execute("DROP TYPE queuedbtype_old")

    # Python-level Column defaults (status, allow_priority, max_capacity,
    # slot_duration_minutes, current_ticket_number) only apply through the
    # ORM, not raw SQL - every column is spelled out explicitly here.
    op.execute("""
        INSERT INTO queues
            (name, queue_type, ticket_letter, description, status, allow_priority, max_capacity, slot_duration_minutes, current_ticket_number)
        VALUES
            ('Adding & Dropping', 'ADDING_DROPPING', 'A', 'Process for adding or dropping subjects.', 'ACTIVE', true, 50, 15, 0),
            ('Petition Class', 'PETITION_CLASS', 'P', 'File a petition for class consideration.', 'ACTIVE', true, 30, 20, 0),
            ('Others', 'OTHER_CONCERNS', 'X', 'Other concerns not listed.', 'ACTIVE', false, 30, 15, 0)
    """)
```

- [ ] **Step 5: Write the `downgrade()` function**

```python
def downgrade() -> None:
    # A Postgres enum value can't be removed while any row still uses it -
    # delete tickets against the 3 new queue types first (only those
    # tickets, not the whole table), then the 3 new queues themselves.
    op.execute("""
        DELETE FROM tickets
        WHERE queue_id IN (
            SELECT id FROM queues WHERE queue_type IN ('ADDING_DROPPING', 'PETITION_CLASS', 'OTHER_CONCERNS')
        )
    """)
    op.execute("""
        DELETE FROM queues WHERE queue_type IN ('ADDING_DROPPING', 'PETITION_CLASS', 'OTHER_CONCERNS')
    """)

    op.execute("ALTER TYPE queuedbtype RENAME TO queuedbtype_old")
    op.execute(
        "CREATE TYPE queuedbtype AS ENUM ("
        "'ENROLLMENT', 'DOCUMENT_REQUEST', 'CLEARANCE', 'SCHOLARSHIP', 'OTHERS'"
        ")"
    )
    op.execute(
        "ALTER TABLE queues ALTER COLUMN queue_type TYPE queuedbtype "
        "USING queue_type::text::queuedbtype"
    )
    op.execute("DROP TYPE queuedbtype_old")
```
