# Ticket Code Letter Prefix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every queue an admin-set, unique single-letter `ticket_letter`, and expose a computed `ticket_code` (e.g. `E-007`) on every ticket-facing response, replacing the plain ticket number everywhere it's shown to students or staff.

**Architecture:** A new required `ticket_letter` column on `QueueDB`, applied via a real Alembic migration (this project has Alembic properly wired up — do not use a drop/recreate workaround). `QueueService.create_queue` rejects a duplicate letter with a 400. `TicketService` gains a small formatting helper that combines a queue's `ticket_letter` with a ticket's existing `ticket_number` counter into a new, purely additive `ticket_code` string field on `Ticket`, `TicketPublic`, and the now-serving-overview response. The frontend's Create Queue form gains a "Ticket Letter" input (pre-filled per queue type, freely editable), and five existing display-consuming views switch from rendering the raw ticket number to rendering `ticket_code`.

**Tech Stack:** FastAPI, SQLAlchemy 2.0, Pydantic v2, Alembic (backend); Vue 3 (Composition API), Pinia (frontend).

## Global Constraints

- `ticket_letter` is a single uppercase A-Z character, set once at queue creation (no "Edit Queue" feature exists today for any field, and this plan doesn't add one).
- Uniqueness is enforced against **all** queues regardless of status (active, paused, or closed) — not just active ones.
- `ticket_number` itself is never changed — same type (`int`), same meaning, same role in per-queue counters and sorting. `ticket_code` is a new, purely additive derived field.
- Format is `<LETTER>-<3-digit zero-padded number>`, e.g. `E-007`. Numbers beyond 999 simply grow (`E-1000`), never truncate or wrap.
- Alembic **is** wired up and working in this project (`backend/alembic.ini`, `backend/migrations/`, current head `db210995aa4a`) — use `alembic revision --autogenerate` + `alembic upgrade head`, not a drop/recreate workaround.
- The DB stores `queue_type` as the enum **member name** (e.g. `'ENROLLMENT'`, `'DOCUMENT_REQUEST'`, `'CLEARANCE'`, `'SCHOLARSHIP'`, `'OTHERS'`), not the lowercase Python value — confirmed by querying the dev database directly. Any raw SQL backfill must match against these uppercase member names.
- Default per-type letters: Enrollment→E, Document Request→D, Clearance→C, Scholarship→S, Others→O.
- No automated test framework is configured for this project; verification is manual against the real running dev stack, using Python `httpx` scripts (curl is unavailable in this environment).
- Seeded dev accounts: `admin/admin123` (Admin), `registrar/registrar123` (Registrar), `staff/staff123` (Staff). The 5 seeded queues (`backend/app/core/init_db.py`): Enrollment, Document Request, Clearance, Scholarship, General Inquiry (this last one has `queue_type=OTHERS`, so it defaults to letter `O`, not `G`).

from alembic import op
import sqlalchemy as sa


# Default letter per queue_type (the DB stores the enum MEMBER NAME, e.g.
# 'ENROLLMENT', not the lowercase Python value 'enrollment' - confirmed by
# querying the dev database directly) - used to backfill existing queues
# before the column becomes NOT NULL.
_TYPE_TO_LETTER = {
    'ENROLLMENT': 'E',
    'DOCUMENT_REQUEST': 'D',
    'CLEARANCE': 'C',
    'SCHOLARSHIP': 'S',
    'OTHERS': 'O',
}


def upgrade() -> None:
    op.add_column('queues', sa.Column('ticket_letter', sa.String(length=1), nullable=True))

    for queue_type, letter in _TYPE_TO_LETTER.items():
        op.execute(f"UPDATE queues SET ticket_letter = '{letter}' WHERE queue_type = '{queue_type}'")

    op.alter_column('queues', 'ticket_letter', existing_type=sa.String(length=1), nullable=False)


def downgrade() -> None:
    op.drop_column('queues', 'ticket_letter')
